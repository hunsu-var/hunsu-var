# 훈수 VAR 디자인 v5 「중계석」 (2026-11-04)

> v4 「빛의 선」 토큰·글꼴·깜이 표정은 그대로 쓰고, 그 위에 깜이가 진행하는 층을 더했다. 사용자 피드백: "너무 딱딱하다, 캐릭터가 설명해 주는 느낌". 레퍼런스: 토스 키워봐요 적금(숫자 위, 캐릭터 해설), Brilliant Koji(말풍선이 데이터를 가리킴), 크리켓 DRS(기준을 차례로 확인), Hawk-Eye·FIFA SAOT(결정 지점에서 멈춤), Spotify Wrapped(큰 숫자 한 개), Apple 활동 링 일시정지(쉼표). 기준은 코드다: `ui/Talk.kt`(말풍선, 장면 그림, 주차 동선, 확인 램프), `ui/Screens.kt`.

- **말풍선 두 가지**: 사람이 한 말 = 흰 말풍선(`SaidBubble`, "조수석" 라벨). 깜이의 말 = 램프 하우징 #17191D 말풍선에 램프 크림 #FFF3DC 글자(`KkamiBubble`), 숫자는 #FFB84D. 밤에는 #3A3F47 테두리.
- **깜이는 진행자, 판정은 데이터**: 판정 단어, "판독 결과 · …" 한 문장, 그림이 판정한다. 깜이는 장면 소개, 질문, 진 쪽 챙기기만 한다(`kkamiSays`). 적중 = 웃는 얼굴(HIT), 기각 = REJECT, 판독 불가 = UNDECIDED. 진 쪽을 놀리지 않는다.
- **판독 중**: 깜이 JUDGING(양쪽 깜빡이만) + 판정 기준 세 개가 램프처럼 차례로 켜짐(`CheckLamps`) + 진행 막대.
- **장면 그림**: 후보 카드마다 장면 종류 스케치(`SceneThumb`)와 미니 깜이(조수석이 찍음 = LISTEN). 주차 판정은 핸들·속도로 다시 그린 동선(`ParkingPathView`: 후진 앰버, 전진 회색, 고쳐 댄 곳 점).
- **빠질 길 그림 (11/5)**: "아까 들어갔어야지!"는 옆 차로가 빈 틈으로 판정한다. 동선 그림의 옆 차로에 빨간 띠(차 있음)와 초록 띠(3초 이상 빈 틈, #2FB67C)를 그리고, 위쪽 괄호에 "옆 차로가 비어 있던 3.5초"를 적는다. 틈이 없으면 예전처럼 "깜빡이 켠 곳 → 빠질 길 N m" 괄호.
- **다음엔 이렇게** 카드는 램프 크림 바탕(밤에는 surface-2).
- **시즌 기록**: 스토리 카드 4장(우리 차 판독 = 먹색, 깜빡이 습관 = 앰버, 이번 주 명판정 = 흰색, 깜이의 규칙 노트 = 크림). 좌석끼리 숫자를 나란히 두지 않는다. 기록 없는 주는 '쉼표'.
- **주행 중**: 말풍선은 정지 상태로만 바뀐다(움직이는 연출 없음). 빠질 길 장면에 훈수를 찍었으면 차가 멈췄을 때 말풍선에 "“…” 판독 결과", 판정 단어, "자세한 건 주차하면 보여 드릴게요"만 나오고 깜이 표정이 판정 표정으로 바뀐다. 근거 문장과 그림은 주차한 뒤에 보여 준다.

# 훈수 VAR 디자인 시스템 v4 「빛의 선」 (2026-11-02)

> v4에서 바뀐 것: 마스코트를 얼룩말 '흑백이'(v3)에서 앞 램프 '깜이'로 바꿨다. 사람다운 얼굴은 판정할 때 오히려 손해라는 근거가 있어서다(조사 노트는 저장소 밖에 있다). 판정은 차의 기계 신호가 내리고, 깜이는 그 신호를 보여 주는 몸이다. 강조색도 호루라기 노랑에서 **깜빡이 앰버**로 바꿨다.
>
> 기준은 코드다: `app/src/main/java/app/hunsuvar/ui/Theme.kt`(토큰), `LampFace.kt`(깜이), `RoadReplay.kt`(증거 장면).
> Figma 작업 파일(비공개)의 페이지 `v4 · 앱 UI`, `v4 · 발표 덱`에서 그렸다. v2·v3 페이지는 보관용이다.

## 원칙

- **진 사람도 웃으며 받아들일 수 있게**: 결과 화면은 누가 졌는지보다 차가 기록한 사실을 먼저 보여 준다.
- **화면의 주인공**: 판정 순간 화면의 주인공은 사람의 승패가 아니라 **차 데이터 한 장면**(점 하나와 법의 선 하나)이다. 판정 단어와 함께 3초 안에 보여야 한다.
- **한 줄 원칙**: 판정은 차의 신호가 하고, 깜이는 그 신호를 몸으로 보여 준다. 증거 층은 정확하고 진지하게, 말하는 층은 부드럽게.

## 깜이 (판독관, 앞 램프 한 벌)

- **생김새**: 차 앞 램프 한 벌을 얼굴로 썼다. 240×120 박스 안에 도형만으로 그린다(`LampFace.kt`).
  - 헤드램프 = 눈
  - DRL = 입
  - 양 끝 앰버 깜빡이 = 볼
  - 사이드미러 = 귀(평소에는 ±20° 벌어져 있다)
- **표정 8종** (`Face`)

  | 표정 | 모습 | 쓰는 곳 |
  |---|---|---|
  | NEUTRAL | 기본 | 주행 중(아직 안 찍음), 판독 후보, 시즌 기록 |
  | LISTEN | 귀가 서고 미러 유리가 켜짐 | 주행 중 '훈수!'를 찍은 뒤, 조수석이 찍은 후보 카드, 훈수 고르기 |
  | JUDGING | 얼굴 없이 양쪽 깜빡이만 켜짐 | 판독 중 |
  | REJECT | 눈이 가로 막대 | 훈수 기각 |
  | UNDECIDED | 한쪽 눈이 꺼짐 | 판독 불가 |
  | HIT | 웃는 눈 | 훈수 적중 |
  | SORRY | 귀가 처짐 | 발표 덱·Figma만 (앱에는 아직 안 씀) |
  | REC | 램프가 꺼짐 | 운전자 동의 전(기록 안 함) |

- **주행 중 움직임**: 없다. Pleos UI 가이드가 주행 중 자동 애니메이션을 막으므로 주행 화면의 깜이는 스스로 움직이지 않는다(깜박임·시선 이동 없음).
  - 깜빡이 램프는 실제 깜빡이가 켜졌을 때만 그쪽 한 개가 켜진다(깜박이지 않고 켜진 채로 있다). 핸들만 꺾었을 때는 켜지지 않는다.
  - '훈수!'를 찍으면 표정이 LISTEN으로 한 번 바뀌고 조수석 쪽으로 기운 채 멈춰 있다.
  - 운전자 동의 전에는 램프가 꺼져 있다.
- **밤**: 켜진 램프를 70% 밝기로 낮춘다. 큰 얼굴이 밤에 눈부시지 않게 하려는 것이다. 테두리에는 얇은 선을 넣는다.
- **대사 규칙**
  - 진 사람을 놀리지 않는다. 진 쪽의 좋은 의도를 먼저 인정한다. 예: "챙겨 준 마음은 잘 받았어요."
  - 대사는 "제 기록으로는 …"으로 시작한다. 판정을 내리는 건 기록이다.
  - 숫자에는 무엇의 숫자인지 붙인다.

- 여백은 48, 요소 사이는 24다.
- **모서리**: 카드 28, 안쪽 상자·칩 20, 버튼은 알약 모양이다.
- **그림자**: 낮에만 쓴다(8dp, 7%). 밤에는 면 색으로만 나눈다.

  - 보조 버튼: 테두리 버튼.

## 화면

- **주행 중 (기어 P가 아닐 때)**
  - 깜이 얼굴이 버튼을 뺀 나머지 공간을 다 차지한다(2:1 비율).
  - 그 아래 폭 전체에 앰버 '훈수!' 버튼(높이 160)을 둔다.
  - 맨 아래 한 줄: 왼쪽에 안내 문구, 오른쪽에 "● 기록 중".
  - 버튼을 눌러도 물결 효과를 쓰지 않는다. 깜이 표정과 말풍선("찍었어요!" / "주차하면 이 장면부터 판독할게요." / "오늘 N개")만이 반응이다.
  - 혼자 모드에는 버튼이 없고, 맨 아래 줄에 "혼자 모드예요. 주차하면 제가 장면을 찾아 훈수를 둘게요."가 나온다.
- **판정 화면** (위에서 아래로)
  1. "조수석 훈수 · “…”" 한 줄
  2. 판정 단어(120)와 판정색 막대, 오른쪽에 신뢰도 칩
  3. 증거 장면(아래 절)
  4. 카드 3장을 가로로: 판정 근거 / 법 조항과 "다음엔 이렇게" / 깜이와 말풍선
  5. 버튼: 다시 보기, 다른 후보, 시즌 기록, 이의 있어요, 둘 다 인정, 공유
- **그 밖의 화면**: 동의, 오늘의 판독 후보, 훈수 고르기, 판독 중, 공유 카드, 지난 판정(목록·상세), 시즌 기록.
- 화면 폭이 1200dp보다 좁으면(반분할) 카드를 세로로 쌓고 스크롤한다.

## 증거 장면 (이 시스템의 서명)

- **도로형** (`RoadReplay.kt`, 1604×420): 거리가 기준인 깜빡이 판정에 쓴다.
  - 위에서 본 도로에서 차가 왼쪽에서 오른쪽으로 달리다 우회전한다. 축은 "40 m … 0 m(핸들 꺾음)"이다.
  - 그리는 것은 세 가지다.
    - 법 기준선(30 m)
    - 깜빡이를 켠 지점의 앰버 핀
    - 깜빡이가 켜져 있던 구간(앰버로 칠함)
  - 오른쪽 위에 범례를 둔다: 기록된 건 우리 차의 거리뿐이고, 주변 도로는 설명을 위해 그린 것이다.
- **동선형** (`Talk.kt` `ParkingPathView`): 주차 판정. 핸들과 속도로 다시 그린 동선(후진 앰버, 전진 회색, 고쳐 댄 곳 점).
- **경로형** (`RoadReplay.kt` `RouteReplayView`): 끼어들기·길 선택 판정. 차가 달린 거리대로 그린 도로에 깜빡이 구간, 옆 차로의 빈 틈, 빠질 길, 재탐색 지점을 표시한다.
- **판독 중 연출**은 1.5초다. 차가 도로를 따라 달리고 지나간 자리가 앰버로 켜진다. 그 과정이 곧 판독 중 화면이다.

## 금지

- 좌석 승패 표시("이겼습니다/졌습니다")를 쓰지 않는다. 진 사람은 상대가 아니라 선에 진다.
- 빨간 기각을 쓰지 않는다.
- 깜이가 판정을 대신하게 하지 않는다. 판정 단어와 근거는 언제나 데이터 층에 둔다.
- 주행 중에는 소리를 내지 않는다. 스스로 움직이는 연출을 쓰지 않는다. 판정 근거와 그림은 보여 주지 않는다(정차 중 한 줄 판정만).
- 다음 것들을 쓰지 않는다:
  - 머리표(eyebrow)
  - 쪽 번호
  - 기울인 고무도장
  - 이모지 아이콘
- 예시 데이터는 화면에 "예시 · 시연 데이터"라고 표시한다.
